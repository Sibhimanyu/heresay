Heresay MVP plan

A web SDK anyone could adopt, used first on our own app, with a straight line from a user's report to our coding agent and back.

The whole loop

1 · USER
Taps Report

In our app, with the screen and version attached.

2 · US
Accept it

In the dashboard. A person always says yes first.

new
3 · BRIDGE
Agent picks it up

Claude Code sees accepted briefs through the Heresay MCP server.

new
4 · AGENT
Fixes the code

In our repo, on a branch, like any other task.

new
5 · AGENT
Marks it fixed

With a one-line note of what changed.

6 · USER
Hears back

Sees "Fixed" and the note in the same app.

Steps 1, 2 and 6 work today. The MVP adds 3, 4 and 5: the bridge to the agent.

Where we are

Getting reports to our agent

MCP server

recommended

Claude Code (and other agents) connect to Heresay as a tool. Ask "fix the next Heresay report" and it lists briefs, reads one, fixes it, and marks it fixed.

CLI

npx heresay briefs, heresay fixed <id> "note". Same API, for scripts, CI, or agents without MCP. Nearly free once the API exists.

GitHub issues

Accepting a report opens an issue. Good for teams, but slower and needs a GitHub app. Later.

What the agent can do (MCP tools)

list_briefs()            // accepted, not fixed, most urgent first
get_brief(id)            // the prompt: type, route, version, user's words
mark_fixed(id, note)     // reporter sees "Fixed" + note
add_note(id, note)       // optional progress, private to you

The agent can only see accepted reports. It cannot read open reports, accept, or decline. Those stay human.

Setting it up in our repo

# 1. dashboard → project → "Agent token" → copy
# 2. once, in the repo:
claude mcp add heresay -- npx heresay-mcp
#    with HERESAY_TOKEN=agt_… in the environment
# 3. then just ask:
> fix the most urgent Heresay report

Tokens are per project, shown once, stored hashed, and can be revoked from the dashboard.
